# 零售门店与商品页面来源约定

`portal.html` 是离线门店目录演练页。每个页面状态含 `scope`、`card_scope`、`phase`、`page`、`page_count`、`page_token` 和本页 `cards`；切换期间 `scope` 会先更新，上一门店的卡片仍留在页面，直到状态变为 `loaded` 且两种门店范围一致。采集器只保存该稳定态页面，并逐卡核对卡片 `store_id` 与页面 `scope` 一致，过渡卡片不进入账本。南方门店第二页会再次列出 `offer-s-1`，其版本与价格已更新，不能把它计作另一项商品或丢掉较新的报价：同一 `(store_id, offer id)` 的多个 revision 合并为一项促销，当前报价取自然序最新版本（本例 v2/14.9 元），被替代的 v1/15.1 元保留在 `history` 中并标注其来源页与收据哈希。页级进度按 `(collection, scope, page)` 记录在 `portal_pages`，卡片与来源页的映射记录在 `portal_page_cards`；同一页面重复接收为空操作，同页原文哈希变化则拒绝覆盖。门店目录只有在已保存页码恰好覆盖 1..page_count 时才标记 `complete=true`，未收齐的必需门店会出现在 `incomplete_required_scopes` 且发布被拦截。`normal.json` 和 `conflict.json` 仍用于账本身份冲突的基线测试。kind、id 和 revision 是来源声明，不能单独证明跨来源业务归属。
